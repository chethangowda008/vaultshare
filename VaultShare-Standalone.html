🛡 Security Architecture
🔑
AES-256 Encryption
Uses AES with 256-bit keys in GCM, CBC, or CTR mode. GCM provides authenticated encryption to detect tampering.
🧂
PBKDF2 Key Derivation
Password is never used directly. PBKDF2-SHA256 with up to 1M iterations and a random 256-bit salt hardens against brute force.
🎲
Random IV Per File
A fresh cryptographically random IV is generated for every encryption. The same file encrypted twice produces different ciphertext.
🔏
Integrity Verification
SHA-256 hash of the original plaintext is embedded. Verified on decryption to confirm the file is byte-for-byte identical.
🌐
Zero Server Contact
All cryptographic operations use the browser's native Web Crypto API. No file data, password, or keys ever leave your device.
📦
Self-Describing Package
Encrypted output carries a structured header: version, algorithm ID, salt, IV, original filename, and hash — needed to decrypt on any device.
📦 Binary Package Format
// .vaultenc binary format (all multi-byte values are big-endian) HEADER { magic : 4 bytes // 0x56 0x4C 0x54 0x45 ("VLTE") version : 1 byte // format version = 0x01 algo : 1 byte // 0=GCM 1=CBC 2=CTR saltLen : 1 byte // 16 or 32 ivLen : 1 byte // 12 (GCM) or 16 (CBC/CTR) iterations: 4 bytes // PBKDF2 iteration count nameLen : 2 bytes // length of original filename hasHash : 1 byte // 0x01 if SHA-256 is embedded } BODY { salt : saltLen bytes iv : ivLen bytes name : nameLen bytes (UTF-8) sha256 : 32 bytes // omitted if hasHash=0 ciphertext: variable // AES-256 encrypted payload }
